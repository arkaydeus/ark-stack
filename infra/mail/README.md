This stack uses the official multi-architecture Stalwart v0.16 image pinned by OCI index digest. A reviewed RocksDB `config.json` is mounted at the image's required `/etc/stalwart/config.json` path; durable data lives under `/var/lib/stalwart`. The installer-provided recovery administrator is passed through `STALWART_RECOVERY_ADMIN`. Incoming mail can start without SES. Outbound sending stays paused until relay credentials are verified. Native administrative routes are exposed only on the private mail-management network.

`mise run mail:up` starts the pinned Stalwart engine. Ark reconciles domains, accounts, mailing-list aliases, lifecycle state, and device credentials through the v0.16 JMAP management extensions after MFA; the public container does not receive AWS, DNS, or root keys. Public ports are SMTP 25, implicit submission 465, STARTTLS submission 587 and IMAPS 993. Listener certificates and relay settings must be observed before Ark marks client or outbound delivery ready.

The service drops every Linux capability and adds back only `NET_BIND_SERVICE`. The pinned image runs as UID 2000 and carries that file capability for its low listener ports; the matching narrow add-back is required when `no-new-privileges` is enabled.
